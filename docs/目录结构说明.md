# 目录结构说明

> 最后整理：2026-10-27

## 一眼看懂

```
Daybreak/
│
│   ┌─ 会同步到 GitHub / Gitee ────────────────────────┐
├── src/                    ← 游戏本体（C# 代码，5 个项目）
├── tools/                  ← 启动器 UI 自动化脚本
├── scripts/                ← 构建 / 打包 / 发布脚本
├── docs/                   ← 文档
├── third_party/            ← 第三方组件
├── .github/                ← CI 工作流
├── Daybreak.slnx           ← 解决方案（引用 src/ 下的项目）
├── Directory.Build.props   ← 统一版本号等 MSBuild 配置
├── README.md               ← 项目介绍
├── AGENTS.md               ← AI 助手交接文档（改代码前必读）
├── THIRD-PARTY-NOTICES.md  ← 第三方许可
└── LICENSE                 ← MIT
│   └───────────────────────────────────────────────┘
│
│   ┌─ 只在本地，不同步 ─────────────────────────────┐
├── website/                ← 官网（含部署脚本与服务器地址）
├── video/                  ← 演示视频（素材 + 制作工具）
└── dist/                   ← 发布产物
    └───────────────────────────────────────────────┘
```

## 为什么有些目录不同步

| 目录 | 原因 |
|---|---|
| `website/` | 部署文档里含服务器 IP，公开仓库不该公示 |
| `video/` | 素材体积大（几十 MB），且含录制时的本地信息 |
| `dist/` | 构建产物，可重新生成 |

**仓库定位是「启动器本体」。** 网站和视频是配套的东西，本地留着就行。

## 各目录干什么

### `src/` — 游戏本体

```
src/
├── Daybreak.Launcher/       WPF 主程序（界面、页面、ViewModel）
├── Daybreak.Core/           启动核心（下载、登录、Mod、服务端、联机）
├── Daybreak.Market/         Modrinth 客户端
├── Daybreak.Updater/        独立更新器
└── Daybreak.Core.Tests/     xUnit 测试（161 项离线 + 22 项联网）
```

**为什么都放 `src/`**：项目之间的引用是兄弟关系（`..\Daybreak.Core\...`），
一起移动后相对路径不变，不用改任何 `ProjectReference`。

只有两处需要跟着改：
- `Daybreak.slnx` 里的 5 条路径（已加 `src/` 前缀）
- `Daybreak.Launcher.csproj` 里引用 `third_party` 的路径（`..\` → `..\..\`）

### `tools/` — UI 自动化脚本

启动器的实机验证工具，改 UI 后必须用它截图验证：

| 脚本 | 用途 |
|---|---|
| `capture.ps1` | 按窗口矩形截图 |
| `capture-safe.ps1` | 安全截图（强制置顶，防止拍到桌面） |
| `click.ps1` | 窗口相对坐标点击 |
| `hover.ps1` | 悬停 |
| `uia-invoke.ps1` | 用 UIA 调用按钮 |
| `uia-nav.ps1` | 用 UIA 切换侧栏导航 |
| `nav-settings.ps1` | 导航到设置页 |
| `dump-uia.ps1` | 导出 UIA 树（排查控件用） |

### `scripts/` — 构建发布

| 脚本 | 用途 |
|---|---|
| `package.ps1` | 打自包含单文件包 → `dist/Daybreak-beta-win-x64.zip` |
| `package-netdisk.ps1` | 打网盘包（版本号命名 + sha256） |
| `publish-gitee.ps1` | 发布到 Gitee 发行版 |
| `make-icon.py` | 生成应用图标 |

### `dist/` — 发布产物

不进 git，可重新生成。

### `third_party/` — 第三方组件

EasyTier 二进制（不进 git，打包时自动下载）、许可证文本、中继地址配置。

## 常用命令

```powershell
# 构建
dotnet build Daybreak.slnx -c Debug

# 跑测试（离线 161 项）
dotnet test Daybreak.slnx -c Debug --no-build --filter "Category!=Integration"

# 实机运行
cd src/Daybreak.Launcher/bin/Debug/net10.0-windows; ./Daybreak.Launcher.exe

# 打包
powershell -File scripts/package.ps1

# 部署官网（香港）
powershell -File website/deploy/deploy.ps1 -Server daybreak-hk

# 重新生成视频配音
powershell -File video/tools/tts.ps1 -ScriptFile video/script-抖音.txt -Rate "+20%"
```

## 整理时踩的坑（记录备查）

### 1. 项目下移一层后 `third_party` 路径要跟着改

```
Daybreak.Launcher/Daybreak.Launcher.csproj    →  ..\third_party\easytier
src/Daybreak.Launcher/Daybreak.Launcher.csproj →  ..\..\third_party\easytier
```

C# 项目之间的引用不用改（兄弟关系没变），但这个跨目录的引用多退了一级。

### 2. `dotnet publish <项目名>` 要带上路径

```powershell
# 改之前
dotnet publish Daybreak.Launcher -c Release
# 改之后
dotnet publish src\Daybreak.Launcher -c Release
```

`package.ps1` 和 CI workflow 都改过了。

### 3. `tools/` 里的脚本不用改

它们找进程用的是**进程名**（`Get-Process Daybreak.Launcher`），不是文件路径，
所以项目挪位置不受影响。

### 4. 有个管理员进程杀不掉

排查时发现 PID 31380（提权启动的启动器实例）锁着 `D:\Daybreak\Daybreak.Launcher.exe`，
普通权限杀不掉（`Access is denied`）。

**影响**：`package.ps1` 最后一步"同步到 D:\Daybreak"会失败，但**打包本身是成功的**。

**解决**：用任务管理器（以管理员身份）结束它，或者注销重登。
